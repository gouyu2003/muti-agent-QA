# 阶段 4.3：可配置协作协议

日期：2026-10-20（Asia/Shanghai）。阶段 4.3 按协议配置管理、Lead 模板、Debate 模板、动态协议 Runtime 和测试验收五项任务组织。本轮六模板整合的实施顺序与结果见 [整合验收记录](protocol-unification-validation.md)。各批相关测试通过后再进入下一批。**实现及离线回归完成，真实模型验收未运行，浏览器人工验收待执行。未提交或推送 Git，未启动或重启 8000 服务。**

## 使用流程

1. 进入“协作协议”，从固定流水线、反馈重试流水线、单专家问答、多专家汇总、Lead Agent、Debate 六张卡片创建自己的协议（新建使用 V2，已有 V1 编辑时保持 V1）。
2. 修改名称、说明、参与人数、入口、阶段类型、参与槽位、执行方式、读取范围、阶段说明、出口规则、循环次数及资源预算。可以添加/删除阶段和出口；执行次序由入口和路由决定，列表上移只改变预览位置。
3. 校验并保存协议草稿；发布协议 v1。每次保存生成不可改写的修订，发布版本也不可覆盖。复制协议会创建新对象。
4. 在“我的系统”新建草稿，先选择已保存个人协议的明确版本或修订，生成相应默认实例；再配置提示词、模型及 Expert/Retriever 的固定知识源版本。Lead 不直接绑定知识源。未选择个人协议不能创建新系统草稿。
5. 在唯一的“执行协议”入口选择明确的发布版本或已保存草稿修订，将角色槽位绑定到系统内的实例。已保存或修改的实例切换协议前需选择保留、生成默认或取消；不同系统可以复用同一协议。
6. 保存系统草稿，再试运行。协议草稿修订可用于试运行；发布系统前必须绑定协议发布版本。
7. 在实时轨迹或历史详情查看每次分派、提案、质疑、修订、审核、路由和用量。升级协议后，旧系统版本继续使用已冻结的协议和材料。

## 首版表达能力与约束

用户配置是数据，不是代码。所有字段和条件均由服务端校验，不执行用户表达式、Python、JS 或任意文件路径。单层并行在一个阶段内展开并等待该阶段实际任务完成，阶段之间顺序执行或条件跳转；没有嵌套图、子图递归或用户节点代码。

| 阶段 | 必需角色 | 行为 |
| --- | --- | --- |
| plan | Planner | 规划子问题；应用阶段说明 |
| retrieve | Retriever | 本地 BM25；阶段说明作为额外检索提示 |
| propose | Expert | 独立初始作答，不读取其他专家观点 |
| lead | Lead | 结构化选择专家、分派具体任务，或汇总提交审核 |
| dispatch | Expert | 只执行 Lead 本轮实际分派的任务 |
| critique | Expert | 对其他专家的当前观点给出同意、质疑或证据不足意见 |
| revise | Expert | 逐条回应针对自己的质疑，提交有引用的修订与修改说明 |
| review | Validator | 基于原文证据判断并写最终答案 |

支持的条件是 always、verified、unverified、lead_dispatch、lead_review、fallback；条件与阶段能力必须匹配。多个出口要求唯一 fallback，运行时最后处理 fallback。静态校验覆盖角色人数、绑定类型、输入阶段、可达性、必需前序阶段、结束路径和循环上限；禁止通过自定义路由绕过 Pipeline/Debate 的必需前序环节。

每个协议 2～12 个阶段，每阶段最多执行 1～5 次，每套系统仍为 1～5 个实例。角色槽位可以跨阶段复用同一实例，但实例不能同时绑定到两个槽位。Debate 的提案、质疑、修订使用同一组至少两个专家；初始独立性来自输入隔离，不保证不同模型或不同结论。

## 身份、输入与输出保留

- `agent_id` 标识可重复使用的智能体实例。
- `stage_id` 标识协议中的逻辑阶段，也是构图阶段节点的身份。
- `call_id` 标识一次独立运行调用，使用唯一 UUID；另记录任务 ID、阶段轮次与调用序号。

同一实例可跨阶段、跨轮次，以及在同一并行阶段承担多个任务。输出按 `protocol_calls[call_id]` 保存，不覆盖旧提案或修订；重复合并内容相同的调用是幂等的，不同内容会报错。调用序号用于排序，不依赖 JSON 字典或并行完成顺序。

每次调用保存实际可见输入、任务、输出、状态及用量。失败调用保留身份、输入、公开错误及实际用量；不保存模型私有思维链或非法原始输出。运行发生异常或取消时保留已完成输出，并只记录一个运行终态。

Debate 每个阶段在开始前冻结输入。初始提案不能读取其他专家观点；质疑指向已有观点的调用 ID，修订通过质疑调用 ID 回应。可配置质疑所有其他专家或按绑定顺序轮转；关闭证据共享时不传递所读阶段的原文证据字段。每位专家仍可检索自己的固定材料。引用必须对应实际提供的证据标识，修订会回填可定位的原文。

Lead 的候选专家来自系统内注册实例，非法专家目标或重复任务 ID 会触发结构化修复，仍无效则失败。专家收到分派任务的具体文本，检索和作答以该任务为输入；未被选择的专家不执行。汇合仅等待本轮实际任务。Lead 和审核者可以读取以前各轮已完成的分派结果，不丢弃早期子任务证据。

## 终止与资源保护

协议同时限制阶段访问次数、节点调用数、模型调用数、保守 Token 预留预算、整次运行时间和单任务时间。预算检查由共享锁保护，覆盖并发与结构化输出重试；超时后停止后续调度。模型请求使用剩余时间作为请求超时。取消和失败会等待在途调用收束，不能撤回服务商已经接收的请求。

`max_reserved_tokens` 使用提示词 UTF-8 字节数加请求输出 Token 上限进行保守预留，包含失败和空输出重试，不等于服务商实际计费用量，也不承诺任意分词器的精确 Token 上限。实际用量独立从模型响应记录；缺失用量保持未知，不记为零。

阶段超限只能结束或进入审核。超限转审核后仍保留 `max_visits` 终止原因；没有完成最终审核的超限结果不会沿用旧的验证通过标记。

`consensus_status` 首版只比较修订答案去除首尾空白并忽略大小写后的文本一致性。界面显示“答案文字一致”等状态，它不是语义共识指标，也不代表证据验证或答案准确性。跨运行记忆、策略自进化、训练及群体共识学习实验未实现。

## 兼容性与数据保护

新增协议目录默认是 `data/protocols/protocols.sqlite3`，可通过 `MAQA_PROTOCOLS_DIR` 指定。它独立保存协议修订和发布版本。`schema_version="3"` 系统快照保存协议原文、明确引用、角色绑定和编译结果，运行时从冻结快照重新校验和编译，不读取最新协议草稿替换历史版本。

旧 schema 1/2 系统仍走原 Runtime；原四种执行模板、CLI、阶段 4.0 V0/V1 实验入口及历史读取保留。没有迁移或改写旧系统与运行记录表，调用账本通过既有结果 JSON 和事件 payload 存储。新增端点用于本地配置界面，不代表对外 API 产品发布或部署。

原阶段 4.3 开发前 Git 工作区干净，原回归检查了 695 个数据文件。本轮六模板整合在既有未提交修改上扩展，已将 37 个初始修改/未跟踪文件复制到被忽略的 `.pytest-tmp-stage43-unified/starting-worktree/`，并对当时的 698 个数据文件记录 SHA-256。清理结果与最终回归详见 [六模板整合验收](protocol-unification-validation.md)。测试使用 `.pytest-tmp-stage43-*` 隔离目录，没有重置工作区、操作已有用户资料或调整依赖版本。
