| 数值比较 | `float(a) == float(b)` | 只比较有限数值，**绝对容差 `1e-6`，相对容差 0**；另出精确相等的敏感性结果 | **C（评分规则变更）** |

**统计证据边界**：已确认公开评分脚本输出按题标准误；二元结果时等于 `sqrt(p(1-p)/N)`。N=100、p=0.85 的计算值为 **3.5707 个百分点，保留一位小数为 3.6**，与原表引用的论文 3.5 并非完全一致。现有证据支持按题标准误这一解释，但未完成论文全部误差数字的独立重算，不能写成“全部吻合”或据此完全排除其他报告细节。新实验明确报告自己的计算公式和分母，保留逐题结果做预先指定的配对比较，不根据误差条重叠判断显著性。

**评分器与敏感性结果**（同一份已保存生成结果离线重算，不新增模型调用）：

1. `author_faithful`：隔离包装作者该提交的评分函数，逐题显式设置原脚本所需的 `pred_solutions`，保留原正则、字符串投票和 `return 1` 行为。全局变量不进入执行核心或并发共享状态。原函数抛异常时记录 `author_scoring_error`；不能擅自把它改成对/错后仍称“原样”。出现异常时报告原脚本无法完成整份评分及异常题目，不通过缩小分母输出可比准确率。此档仅用于对照公开代码，不证明论文发表数字一定由该提交生成。
2. `fixed`：主报告口径，遵守上表解析、字符串计数、最高频平票先出现、绝对容差 `1e-6` 的规则。分式、多个相互冲突的最终答案或其他不支持的最终格式按解析失败记录；不静默取分母、较早的中间结果或进行单位换算。
3. `sensitivity.tie_error`：仅将 fixed 中“最高频并列”改为判错，其余条件不变。**不是严格多数**：例如 6 票为 `[A,A,B,C,D,E]` 时 A 是唯一最高频，仍可获选；严格多数须超过 3 票，本轮不将其混入该变体。
4. `sensitivity.exact`：仅将 fixed 的最终数值比较改为去除容差后的精确数值相等，其余条件不变。不同时改变投票和容差，便于逐题定位差异。

任何 fixed/faithful 或敏感性变体的差异都对应到具体题目。执行失败不伪造成一段 None 输出交给 faithful 算对；保留生成失败与评分错误的不同状态。原样评分全部完成时才报告它与 fixed 的完整准确率差，否则保留逐题对照并说明原样评分未完成。

## 4. 消息结构与同轮隔离（实现约束）

Debate、第 2 轮、agent i 的请求 messages 必须精确等于：

```
[0] user      初始提示
[1] assistant 该 agent 第 1 轮回答
[2] user      辩论更新提示（内含其他 2 个 agent 的 [1] 内容）
```

三条硬约束：

1. `[2]` 中引用的同伴内容取自**对方 context 的索引 1**（绝对位置），不是"最后一条"。
2. agent 之间**串行**，agent i 构造 `[2]` 时，同伴可能已生成本轮新答案，但**不得使用**。
3. agent i 的 `[1]` 必须保留在历史中；第 3 轮及以后（若扩展）继续累积，不截断。

离线自检的判定口径（第 3 步用假模型验证）：同一轮内，任一 agent 的请求 messages 中不得出现"其他 agent 在本轮新生成的文本"；伪造一份带标记的假模型输出，检查标记是否只出现在下一轮。

## 5. 已离线核实的缺陷与影响

以下均为本次在本机实跑复算的结果（未调用模型）。

### 5.1 标准答案侧：100 题中 **2 题的标准数值被截断**

`eval_gsm.py:70` 用 `solve_math_problems(gt)` 取全文最后一个数字，遇到千分位逗号会只取到最后三位：

| qid 位置 | 标准答案 | 作者脚本解析为 | 后果 |
| --- | --- | ---: | --- |
| 样本第 62 题 | `1,450,000` | `000` | 有效解析为 1450000 时被判错；解析为 0 反而判对 |
| 样本第 91 题 | `5,600` | `600` | 同上 |

**含义：若 100 题均给出有效、正确的数值答案，这两题可能被原脚本误判。不能据此称“原样评分理论上限98%”**：错误数值可能碰巧匹配被截断的标准值，解析失败还可能触发算对缺陷。原表另记录全 test 中有 14 条千分位答案、2 条负答案。实际影响须对同一份输出逐题比较 faithful 与 fixed，不能给所有结果机械加/减 2 个百分点，也不能把论文与本复现的总分差直接拆成已知的模型或抽样贡献。

### 5.2 预测侧解析边界（实跑结果）

| 模型输出 | 作者链式解析结果 | 评价 |
| --- | --- | --- |
| `\boxed{72}` | 72 | 正常 |
| `\boxed{1,450,000}` | 1450000 | 正常（侧内含逗号时正则允许逗号） |
| `\boxed{\$72}` | 72 | 正常 |
| `\boxed{-72}` | **72** | 符号丢失（标准答案侧也丢，通常相互抵消） |
| `\boxed{72.5}` | 72.5 | 正常 |

| `\boxed{3\frac{1}{2}}` | 2 | 分式无法解析（GSM8K 罕见） |

### 5.3 投票实现

- `most_frequent()`：`num = List[0]`，空列表会 `IndexError`；平票取**最先出现**者，不要求严格过半。
- 解析失败的 `None` 会进入计数列表；若 `None` 成为最高频，`compute_accuracy` 走到 `pred_answer is None → return 1`，**整题记为正确**。
- `compute_accuracy` 的 list 分支遍历的是**全局** `pred_solutions`（`eval_gsm.py:78`），而不是入参 `pred_solution`。在 `__main__` 里恰好能跑通；一旦被当作模块导入复用就会 `NameError`。这是必须消除的隐式依赖。

fixed 消除该隐式依赖；faithful 仅在隔离的作者脚本包装内按题显式提供它，以对照原行为，不能把“保留全局 bug”当作执行核心的实现要求。最高频投票（plurality）、平票判错和严格多数（超过有效票数一半）是不同规则，不能互换名称。

### 7.2 选型与结论约束

1. **采用普通文本解释、关闭可配置的独立 reasoning 模式。** 各模型的候选参数须分别验证；不能只凭模型名称、字段是否存在或 Token 长短判断。保留作者要求的自由文本解释，不增加推理或格式提示词。
2. **优先使用明确版本的模型 ID。** 日期后缀提高请求可追踪性，但是否为不可变权重须有供应商说明；仅冻结 ID 或 `/models` 哈希不等于冻结远端权重。弱臂没有版本 ID 时如实记录漂移风险，不与“必须 dated”的要求同时宣称已满足。
3. **记录能力区间和天花板影响，不据 test 成绩换模型。** 主臂结果无论增益方向均报告。弱臂仅依据独立 train 校准选型；两个模型上的增益差异只是有限条件下的观察，不能单独证明“能力越弱，辩论增益必然越大”。

**主臂选 `deepseek-v4.1-flash-1017` 的理由（按重要性）**

2. **复用排查经验**：原平台提供了关闭思考及参数兼容的经验，候选参数可据此起步；对新入口、显式模型 ID 的行为仍须第 4 步验证。

**弱臂为什么不在现在就拍定**

不能从模型名称、参数规模或未经本轮验证的外部准确率认定它“弱”。train 校准只用于按预设规则选型；30 题准确率本身有较大不确定性，不等于该模型在正式 test 或其他数据上的真实能力。

因此弱臂由校准结果决定，准则事先写死：

1. 使用 2.3 的 **`train_calibration_30.json`**，与 10 道 train 调试题互斥；**不使用正式 test 清单的前30题**。同一份 train 30 题 × 3 个模型 × Single = 90 次正常生成，额外探测/重试另记。
