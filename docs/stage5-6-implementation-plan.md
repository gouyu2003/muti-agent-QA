## 1. 目标与阶段边界

本轮研究准备问题：在固定任务、模型和明确资源约束下，基础单智能体与多智能体方法的回答质量、运行开销和可观察错误有何差异？

- 阶段 5：完成可配置、可复现、可中断恢复的评测工具，以及基础对照方法接入。
- 阶段 6：完成方法比较、逐题诊断和人工审阅工具。用户运行后，才能形成真实基线报告与错误分析结论。
- 本轮首先交付“可执行实验工具”，不把代码验收当作论文实验完成。
- 不强制 Pilot-100。真实运行的样本数、模型和预算由用户决定；少量试跑由用户手动发起。
- 不要求现在确定最终论文题目。开发集分析可用于选择后续研究方向，但不能预先保证群体记忆或自进化有收益。

本轮不开发实验可视化网页、跨运行记忆、自进化算法、公开 API 产品或异机迁移。保留现有系统管理、问答、历史与旧实验入口；不以此方案授权重启服务、修改日常数据库、提交或推送 Git。

## 3. 首批方法与比较含义

以下为建议默认实验设计，可在开发前调整，不代表用户已经授权真实运行。

| 实验方法 ID（拟定） | 执行定义 | 主要用途 |
| --- | --- | --- |
| `single_rag` | 原问题直接检索，再由一个 Expert 作答并输出引用 | 简单参照 |
| `pipeline_fixed` | Planner → Retriever → Validator，一次流程结束 | 基础多角色流水线 |
| `pipeline_adaptive` | 同一流水线，允许证据不足补检索、冲突重规划 | 检查反馈机制的质量与成本 |

三个方法使用相同模型与可见语料、相同基础 BM25 参数和答案格式约定。固定与自适应组共享初始角色配置，明确记录反馈规则差异。所有参数在运行前冻结，不根据本轮答案临时修改。

首批优先使用 V2 的 `single_expert`、`pipeline`、`pipeline_feedback` 作为执行实现。`single_rag` 要验证确实以原问题检索，不经过隐藏规划流程；单次逻辑作答与结构化输出重试分开计数。

首轮属于端到端系统比较：规划和重检索会改变最终证据，不能声称已单独证明“协作本身”的因果收益。若后续研究需要隔离协作效果，再设计共享固定检索证据的专门对照。

基础 BM25 Retriever 是确定性节点，不计算为 LLM 智能体调用。方法名称不能掩盖实际 LLM 数量与执行流程。

多专家、Lead、Debate 不强制纳入首轮真实实验。它们后续通过相同方法接口接入，并分别完成工程验收。自行实现的通用模板不是某篇论文方法的已验证复现。

外部 baseline 的接入先形成候选记录：论文与代码来源、适用任务、核心机制、许可证、模型与材料条件、适配差异、复现成本。最终按研究问题选代表方法，不将任意开源项目或本文三组视作论文最终全部基线。外部方法的完整复现另行确定范围。

## 4. 数据与比较规则

### 4.1 数据清单

首版以 HotpotQA distractor 为数据适配目标，数据由用户提供本地路径，不自动下载。准备过程记录来源、文件 SHA-256、有效样本数、重复 ID、数据版本及标签格式。

通用清单至少包含：schema 版本、dataset hash、用途、抽样算法与 seed、抽样策略、样本 ID、题型及清单哈希。相同输入与 seed 得到相同清单，不能按模型回答结果挑题。

- `development`：错误分析、调参和方法选择；不能包装成独立最终测试。
- `evaluation`：预先保留、独立评价；执行前检查与已登记 development 清单不重叠。
- `smoke`：少量工程试跑；若与开发数据重叠应显式记录，不能与保留评价数据混用。

若使用官方 dev 的子集自建划分，报告明确称为“dev 内部划分”，不称为官方 test。已人工分析的旧 Smoke-10 ID 默认加入最终评价排除清单；准备时汇总既有开发清单中的已知暴露 ID。工具只能检查已登记数据，不能保证未知历史暴露不存在。

默认按题型保持源数据比例抽样，也允许显式等量抽样；报告记录选择方式和实际比例。样本数不足、ID 重复、用途重叠或哈希不符时拒绝执行，不静默换样本。

未来开展记忆研究时，再增加经验构建集及实体/关系泄漏检查；仅 ID 不重叠不足以保证记忆研究无泄漏。本轮不实现记忆构建。

### 4.2 Runtime 数据边界

每题独立建立 context，只向问答 Runtime 提供题目 ID、question 和 context。answer、supporting_facts 以及题型/难度等评测元数据只供评测端使用，不注入模型提示词或检索器。

执行顺序：冻结方法定义 → 创建当前样本的公开上下文 → 编译派生运行快照 → RunService 执行 → 评分端读取标签。不同题目的检索器与状态不得串用。

既有系统发布版本如被选为方法来源，只读取其固定版本并导出实验局部快照。逐题材料替换是明确的实验变换：记录原版本指纹、适配器版本和每题派生指纹；不写回原系统，不把派生快照冒充原发布版本的原样执行。所有声明的检索槽位都要绑定当前题 context；缺失绑定或混入日常材料必须拒绝。

### 4.3 模型与预算

执行前冻结模型/服务标识、提示词、温度、输出限制、请求策略、检索参数、重试规则、协议上限、重复次数与执行顺序。密钥仅从环境读取，不写入配置、日志或源码包。

首轮以相同资源上限下的质量与实际成本比较为主，不强迫不同方法消耗同样 Token。记录逻辑轮次、结构化修正、请求重试的区别，计入实际调用与用量。未来如需等成本比较，应另设预算实验，不从本轮自动推出等成本结论。

默认样本和方法依次执行，不在方法间并发，以降低服务竞争影响；支持预先固定并记录的方法顺序轮换。协议内部并行性独立记录。一次延迟观测不作为稳定性能保证；报告显示执行时段、重复数及限制。

费用只有在用户提供带日期、币种及用量类别的价格配置后才估算；否则报告 Token，不猜价格。未知用量为 null，不能当零。

## 5. 执行、持久化与恢复

### 5.1 实验目录

拟将实验产物放在被忽略的 `data/experiments/<experiment_id>/`，每个实验保存：

```text
config.resolved.json       # 冻结后的配置，无密钥
manifest.json              # 样本与用途
provenance.json            # 代码、数据、依赖、模型和适配器身份
methods/                   # 固定方法定义与来源
contexts/                  # 仅公开上下文
tasks.sqlite3              # 样本 × 方法 × 重复编号的任务及尝试账本
runs.sqlite3               # RunService 运行与事件
logs/                      # 执行日志
results.jsonl              # 可重建的逐题结果导出
predictions/               # 按方法与重复编号导出的官方格式预测
reports/                   # 汇总、比较、诊断与人工审阅材料
```

SQLite 账本与运行记录为恢复依据，JSONL 和报告是派生产物，不能仅凭文本行数判断已完成。终态、评分和导出之间中断时，根据 run_id 对账；已有有效终态仅重新评分/导出，不重新调用模型。

### 5.2 中断与再次尝试

- `resume` 默认仅执行未启动任务，跳过已完成及已失败终态。
- 失败保留在分母与历史记录中；重新尝试必须显式使用重试参数，并保存新的 attempt，不能覆盖旧结果或择优挑分。
- 报告默认使用预先定义的首次尝试；补跑表现单列。原实验与新增尝试的总开销分别报告。
- Ctrl+C 停止派发后续任务，尽量等待在途请求收束。不能保证撤回已发给服务商的请求。
- 强制关闭时若请求是否完成不明，标记 interrupted/unknown。再次请求可能重复计费，需用户显式选择重试；不承诺远端 exactly-once。
- 恢复前核对代码、方法、样本、模型配置及评分版本。执行配置变化需新建实验，不拼接成一个运行。
- 为实验设置单执行者锁，防止两个终端同时执行相同任务。意外退出后按明确的锁恢复规则处理。

所有存储使用实验目录，离线测试使用临时目录；不把试验数据写入用户日常系统、知识或运行数据库。

## 6. 指标与报告规则

| 指标 | 定义与边界 |
| --- | --- |
| Answer EM/F1 | 按官方评分语义；失败和超时计零，拒答按实际输出评分 |
| Supporting Facts EM/F1 | 使用可验证的标题与句子坐标；不能把文本近似匹配当准确坐标 |
| Joint EM/F1 | 按官方公式实现，不把两个 F1 简单相乘冒充 Joint F1 |
| 检索覆盖 | 原始检索事件中实际可见的唯一句子与 gold facts 对比；初次与全部轮次分开 |
| 调用与 Token | 报告总量、每题均值、用量覆盖率，并包含失败与重试实际开销 |
| 延迟 | 报告每题执行时间 mean/median/P95；实验总墙钟、等待及恢复时间另记 |
| 可靠性 | completed、failed、cancelled、interrupted、not-started 分开统计 |
| 内部 verified | 独立展示，不能替代标准答案正确率 |

检索覆盖不等于最终引用匹配；一个 chunk 覆盖多句时记录明确映射，无法可靠映射则记未知。不同方法检索次数不同，默认汇总叫“累计支撑事实覆盖率”；只有 k 的检索单位明确且一致时才称 Recall@k。

完成实验的主表以完整固定清单为分母。部分运行报告标记 incomplete，展示已执行/计划数与覆盖率，不将已完成题的平均分冒充全实验结果。所有方法任务完整且覆盖同一清单后才生成正式比较状态。

输出总表、bridge/comparison 分组、逐题配对差异、胜/平/负数量及预设的配对 bootstrap 区间。重采样 seed 和次数写入报告，重复运行先保留层次再按规则汇总；样本重采样区间不替代模型多次运行稳定性验证，不自动宣称统计显著。

保留官方格式预测以供复核。评分代码变动时另存带版本报告，不改写原始预测。

## 7. 阶段 6：错误诊断与人工审阅

自动输出可观察标签，而不是自动给出因果结论：

- 运行失败、超时、结构化输出错误、引用无效。
- gold 支撑事实未完全出现在检索记录中。
- gold facts 已覆盖但答案不匹配。
- 答案正确但支撑事实不匹配。
- 内部验证通过但外部评分错误，或未通过但答案正确。
- 新一轮检索未增加证据、调用增加但结果未改善等描述性现象。

人工审阅表保存 sample_id、method_id、run_id、原答案、gold、证据、评分、诊断标签、相关事件，以及人工判断/不确定性/备注。机器标签和人工标签分开保存，人工语义判断不能覆盖官方 EM/F1 或直接修改 gold。

样例选择规则预先固定，例如每类按 sample_id 哈希顺序取最多若干例；不只挑有利案例。保存同题不同方法的对照，支持分析检索、规划、回答、审核环节，但最终归因仍需证据和必要的消融验证。

报告应明确区分：观测结果、解释假设、下一步验证。工具模板不自动生成“证明方法有效”等科研结论。

## 8. 拟定命令与用户工作流

以下全部是待开发的目标接口，当前不能执行。示例路径是拟定交付路径；实际交付时会提供完整配置文件与真实可用命令，不要求用户猜参数。

```powershell
# 1. 本地校验数据并生成固定清单，不调用模型
.\venv\Scripts\python.exe -m src.evaluation.experiment prepare --config experiments/baselines.local.json

# 2. 展示方法、任务数、预算上限和输出位置，不调用模型
.\venv\Scripts\python.exe -m src.evaluation.experiment preflight --config experiments/baselines.local.json

# 3. 用户手动开始真实运行；没有 allow-model-calls 时拒绝联网执行
.\venv\Scripts\python.exe -m src.evaluation.experiment run --config experiments/baselines.local.json --allow-model-calls

# 4. 用户手动恢复未启动任务，不重新执行已有终态
.\venv\Scripts\python.exe -m src.evaluation.experiment resume --experiment data/experiments/baseline-dev-001 --allow-model-calls

# 5. 显式补跑失败或状态不明任务；保存新尝试，不覆盖首次结果
.\venv\Scripts\python.exe -m src.evaluation.experiment resume --experiment data/experiments/baseline-dev-001 --retry-status failed,interrupted --allow-model-calls

# 6. 本地重新生成指标、比较表及人工审阅材料，不调用模型
.\venv\Scripts\python.exe -m src.evaluation.experiment report --experiment data/experiments/baseline-dev-001
```

配置文件拟包含：dataset 路径、用途清单、sample_count/seed/抽样策略、methods、模型及检索配置、资源限制、repeats、输出目录和诊断抽样规则。凭据来自环境，不放配置文件。

终端显示任务进度、方法、样本 ID、状态、耗时及已知用量；完整信息持续写盘。普通终端运行需要电脑不休眠、进程仍在运行，关闭后使用恢复命令；本轮不增加后台调度服务。

## 10. 开发与首次真实运行前的决定

可以先按本方案默认的 HotpotQA distractor、三组基础方法、端到端比较、终端执行开展工具开发。以下事项不应被默认为用户已经确认的实验事实：

| 决定 | 最晚需要确定的时间 |
| --- | --- |
| 是否调整首批三组方法及比较目标 | 对应方法适配开发前 |
| 本地数据位置、开发/评价用途清单、样本数量 | 用户首次 prepare 前 |
| 模型、资源上限、重复次数 | 用户首次 run 前 |
| 是否找回并加入历史 V0/V1 | 历史方法运行前，不阻塞新工具 |
| 外部代表方法、最终论文问题和独立评价设计 | 对应方法接入与最终论文实验前 |

本次“可以”确认的是先形成实施方案，不等同于开始代码实现、模型调用或 Git 交付。下一步代码开发可以按 A～E 分批推进，真实模型运行始终由用户手动发起。
