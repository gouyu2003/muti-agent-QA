# 诊断、运行生命周期、耗时和中文检索

日期：2026-11-06。适用于本次新增运行；旧档案缺少的信息显示“未记录”，不会根据新代码补造历史数据。

## 页面使用

- **实时问答**：运行提交到独立后台进程。刷新、断网、切页或关闭页面不取消执行；同一浏览器保留当前运行标识，重新打开后继续订阅已有轨迹。页面连接与后台状态分别展示，明确点击“停止运行”才请求取消。
- **停止运行**：先显示“正在停止”，等待执行端确认。停止后保留已完成节点；正常完成结果若已持久化，不被随后到达的取消请求覆盖。远端未返回请求的结果和用量保持未知。
- **运行历史和逐题评测**：使用统一诊断区，区分最终失败和重试后完成，展开查看具体业务错误、字段位置及本地请求/协作调用编号。运行历史诊断筛选同时作用于列表、统计和 JSONL 导出。
- **耗时分析**：显示加载、检索、模型等待、重试等待、输出修正、保存等区间，以及阶段/请求关联。实际经过时间合并同类重叠区间；累计工作耗时保留各任务之和。不同环节可能嵌套，不能相加。原 `duration_ms` 执行耗时口径保留。
- **知识源**：新导入材料支持中文、英文与混合文本。详情显示索引版本和“检索试查”，可选择 Top K，查看排序、分数、原文与行号。试查只执行本地检索，不调用模型。相关性分数不表示答案正确率。

## 接口

| 方法与路径 | 行为 |
| --- | --- |
| `POST /api/v1/qa/runs` | 返回 202 与运行 ID；接受原问答选择字段和 `client_request_id` |
| `GET /api/v1/runs/{id}/status` | 返回准备启动、运行、请求停止或终态，以及心跳、最后进展、活动和耗时 |
| `GET /api/v1/runs/{id}/events/stream?after_sequence=-1` | 订阅已保存事件；SSE `id` 为轨迹序号；活动快照使用 `run_activity` |
| `POST /api/v1/runs/{id}/cancel` | 幂等请求取消；已结束时返回已有终态 |
| `POST /api/v1/knowledge/sources/{id}/versions/{version}/search` | 请求 `query` 和 `top_k`，默认返回前 5 条固定版本片段 |

相同 `client_request_id` 与相同请求内容返回同一运行；内容改变返回 409。提交响应丢失时可使用相同编号重试。单个工作区一次运行一项实时问答；批量评测保持独立 worker 和既有启动确认。

原 `POST /api/v1/qa/stream` 保留兼容事件格式，内部同样提交后台执行。原 `GET /api/v1/runs/{id}/events` 继续返回 JSON 列表。旧的直接消费 `RunService.stream()` 的 CLI/测试代码仍按其消费者生命周期收尾。

## 执行、存储与兼容

- 默认运行库为 `data/runtime/runs.sqlite3`。实时 worker 日志和执行锁位于相邻的 `runs-interactive/<运行ID>/`；更换运行库路径时按相同规则隔离。
- 日常运行库增加 `interrupted` 终态，V1 升级前使用 SQLite backup 保存 `.v1-backup`；状态和结束事件在一个事务内提交。新观测保存于独立表，以运行 ID 索引。
- 心跳约每 2 秒更新；超过 15 秒未更新时显示核查提示，不仅凭没有新轨迹判定失败。结束进程通过持有/释放执行锁核对，不根据可能复用的 PID 猜测。
- 实时进程先用标准库入口持有执行锁并更新心跳，再加载运行依赖；启动导入最长 120 秒。启动期间也可以停止，避免冷启动被误判为遗留运行。
- 显式取消先协作收尾，5 秒收尾期后仍未退出则结束该运行专属进程。请求、节点和整题沿用有界时间限制；批量任务同样具有运行超时看护，进程退出后核对账本和已保存结果，不自动重发未知请求。
- 批量暂停仍等待当前题结束。继续未开始的题与补跑已有尝试保持分开，首次成绩不被替换。损坏或不完整账本拒绝重构。
- 旧实验档案通过只读连接读取，不迁移或改写。代码更新后，旧冻结任务仍按原有源码/依赖指纹检查；需要变更执行条件时复制配置、重新预检并新建任务。
- 诊断只新增应用编写的错误信息与关联编号，不新增完整提示词、原始无效响应或私有思考内容日志。模型供应商信息继续走原脱敏逻辑。

## 中文检索的范围

新含中文材料使用 `bm25-zh-mixed-v1`，混合中文单字/双字片段与英文数字词项。规范化仅用于索引和查询，引用保留原文字节对应的行号和字符位置。已有 `bm25-en-v1` 的分词及排序不变；不原地重建旧知识源。

中文跨跳候选取自前跳原文中的引号实体、标题实体及固定机构/地点规则，数量有界。该能力不等同于通用中文命名实体识别或语义检索。材料格式仍为 UTF-8 TXT/MD；中文长答案评分、PDF/OCR 和向量检索不在本轮范围。

固定回归材料位于 `tests/fixtures/chinese_retrieval.json`，包含 30 条预标注样例，其中 25 条有答案（含 5 条跨文件依赖）、3 条无关查询、2 条相关但材料缺少所问事实的查询。后两类分别验收，检索命中不等于存在答案。材料为虚构示例，不代表真实学校或企业制度，仍需人工复核，不能据此报告真实领域问答效果。

## 验证与异常记录

后端测试通过临时数据库、假模型和本机隔离子进程验证幂等提交、断连后继续、序号续读、取消与完成竞争、进程中断、强制收尾、数据库迁移/事务回滚、只读档案和中文引用位置。前端测试使用固定假请求；页面验收服务使用独立 8015 端口和临时数据，不占用日常 8000 服务。

最终验证记录：

- 后端完整回归共 456 项：455 通过，1 项在临时 JSON 文件替换时出现 Windows `WinError 5`。随后使用短临时目录，复验原失败项及最后的修改，共 76 项全部通过；没有修改原有 JSON 原子写入逻辑。原失败文件路径未超过 260 字符，文件也未设只读，不能据此断言是路径长度限制，访问失败的系统原因尚未确认。
- 前端 19 个测试文件、101 项测试全部通过；类型检查与生产构建通过。完整组件回归使用单测试进程、15 秒单项上限，避免并发构建和复杂组件渲染触发默认 5 秒超时。
- 30 条固定检索样例通过回归：有答案题达到 Hit@5 90% 的验收阈值，5 条跨文件依赖均能传递目标实体并命中后续证据；相关但无答案与完全无关分别检查。人工复核仍待完成。
- 固定假模型页面验收确认检索试查、刷新后恢复同一运行、固定知识源与版本展示、显式停止后确认取消，以及桌面和手机宽度下无页面横向溢出。隔离验收服务已停止。

本轮早期测试存在一次隔离错误：假模型未传入新建的生产子进程。两个早期回归目录共记录 **12 次意外模型请求**，实际费用未核对。后续已增加测试内执行注入、父进程外部网络拦截，以及继承到子进程的 `MAQA_DISABLE_MODEL_CALLS=1` 开关。常规离线测试不使用真实模型；显式 integration 测试不自动设置此开关。

正式评价 `baseline-evaluation-001` 的原配置、清单、数据库、方法定义、源码归档及报告等 24 个关键文件已与原完整性清单核对，哈希全部一致。上述意外请求只发生在独立测试目录，没有重跑或覆盖正式实验结果。

## 使用前

按原方式重启后端与前端，加载新接口和页面。无需重新安装依赖。已有英文材料继续可用；需要中文索引时导入新的材料版本。原有模型凭证仍从本机环境获取，不进入导出档案。
