# 全流程手动测试：创建并运行一个个人问答系统

用例编号：MANUAL-FLOW-001

本用例覆盖知识源导入、个人协议创建与发布、系统配置与发布、实时问答、运行历史及路由刷新。材料中的人物、机构和城市为测试用的虚构数据。

本文件是待执行的手动测试说明。准备材料和检查本地解析结果，不代表真实模型问答已经验收通过。

## 准备

- 启动前后端，打开 http://127.0.0.1:5173，确认页面显示“服务正常”。
- 确认当前配置的模型接口可用。规划、审核实例沿用当前可用模型和默认提示词。
- 上传材料为同目录 materials/ 下的 people.md、institutes.md，共两个英文 UTF-8 Markdown 文件。
- 本轮使用新建知识源的版本 1。协议与系统都创建为新对象，第一次发布版本应为 v1。

本轮命名：

| 对象 | 名称 |
| --- | --- |
| 知识源 | 全流程测试材料-01 |
| 协议 | 全流程测试协议-01 |
| 系统 | 全流程测试系统-01 |

如已有同名对象，可以统一换成后缀 -02，并在后续步骤使用同一组名称。

## 1. 导入知识源

1. 进入“知识源”，确认地址路径为 /knowledge。
2. 导入目标选择“创建新知识源”，名称填写“全流程测试材料-01”。
3. 同时选择 people.md 和 institutes.md，点击“导入材料”。
4. 确认导入成功，状态为“可用”，版本为 1。
5. 在材料预览中检查两个文件的原文。

预期：文件数为 2，按当前解析规则应产生 2 个片段；可以看到以下两个事实：

- people.md 第 3 行：Mira Solen founded the Aster Vale Research Institute.
- institutes.md 第 3 行：The Aster Vale Research Institute is located in Bellhaven.

这一步完成后，直接切换到“协作协议”，继续配置个人系统。

## 2. 创建并发布个人协议

1. 进入“协作协议”，确认地址路径为 /protocols。
2. 点击“从 固定流水线 创建”。
3. 协议名称填写“全流程测试协议-01”。
4. 协议说明填写“用于验证材料导入、系统配置、问答与历史记录的完整流程”。
5. 保留模板中的角色、阶段、出口及执行保护参数。
6. 点击“校验协议”，预期显示校验通过。
7. 点击“保存协议草稿”，确认保存成功。
8. 点击“发布协议版本”，确认存在发布版本 v1。

预期执行顺序：plan → retrieve → review → END。

## 3. 配置并发布系统

1. 进入“我的系统”，确认地址路径为 /systems。
2. 点击“新建系统”，系统名称填写“全流程测试系统-01”。
3. 在“执行协议”的“我的已发布协议”分组，选择“全流程测试协议-01 · v1”。如果列表尚未更新，点击“刷新协议列表”。
4. 保留自动生成的三个智能体实例；确认各槽位绑定了正确角色的实例。
5. 可把实例分别重命名为“流程测试-规划”“流程测试-检索”“流程测试-审核”，按下面的表核对配置。

| 协议槽位 | 对应实例角色 | 本轮配置 |
| --- | --- | --- |
| planner | 规划 | 当前可用模型；默认提示词及其他默认参数 |
| retriever | BM25 检索 | 知识源“全流程测试材料-01”；固定材料版本 1；检索 top_k = 5 |
| reviewer | 回答与审核 | 当前可用模型；默认提示词及其他默认参数 |

6. 确认没有“知识源待配置”“请选择固定知识源版本”或实例绑定相关提示。
7. 点击“创建草稿”，确认保存成功且不再提示有未保存修改。
8. 点击“发布版本”，确认系统存在发布版本 v1。
9. 在“已发布版本（只读）”中选择 v1，点击“使用此版本问答”。

预期：自动进入 /run；运行区域显示“全流程测试系统-01 · v1”，并显示检索实例绑定的材料版本 1。

知识源配置在检索实例内；规划与审核实例不需要选择知识源。若发布按钮不可用，应先检查协议是否选择发布版本、配置是否完整、修改是否已保存。

## 4. 实时运行

核对当前显示的是刚才发布的系统，然后粘贴以下英文问题：

> In which city is the institute founded by Mira Solen located?

点击“开始协同问答”，等待运行结束。记录页面上实际显示的答案、验证结论与证据。

预期：

- 规划、检索、回答与审核阶段按协议完成。
- 最终答案明确为 Bellhaven，允许句式和标点不同。
- 证据覆盖“人物 → 机构”与“机构 → 城市”两个关系，可以追溯到 people.md 和 institutes.md 的原文及材料版本 1。
- 验证结论为通过。

人工核对的证据链：

Mira Solen → Aster Vale Research Institute → Bellhaven

“执行完成”与“答案正确”分别检查。答案、证据或验证结论不符合上述预期时，记录为未通过，不因运行已完成就判定成功。

## 5. 检查运行历史和刷新

1. 进入“我的系统”，选中“全流程测试系统-01”。
2. 点击“查看此系统历史”。
3. 确认路径为 /history，查询参数包含 systemId；参数值是实际系统 ID。
4. 找到刚才的问题，打开对应运行记录。
5. 记录运行 ID（run_id），核对所属系统及发布版本 v1、答案 Bellhaven、运行状态、证据和智能体配置。
6. 在“本次智能体配置”中核对检索实例使用“全流程测试材料-01”的版本 1。
7. 刷新浏览器，再次打开同一运行 ID 的记录，确认仍能看到相同答案、证据和版本信息，系统筛选参数仍保留。

进入历史页面或刷新页面应读取已有记录。一次手动启动的问答不应因为这两种操作而额外生成新运行。

## 通过标准与记录

- [ ] 系统三个角色绑定正确，检索实例绑定材料版本 1，系统 v1 发布成功。
- [ ] 实时运行使用目标系统 v1，得到答案 Bellhaven。
- [ ] 答案的两个必要关系均有上述原文证据，验证通过。
- [ ] 历史记录属于目标系统和版本，刷新后仍存在。
- [ ] 五个页面使用各自路径；系统历史筛选保存在 URL 中。
