## 设计取舍

优先保留最终评价的 1,000 道不同题和六方法同题配对，削减开发规模与真实模型重复数。最终评价每题每方法只运行一次，因此不能报告三次重复的均值、标准差，也不能据此估计模型调用随机性的波动。现有按题 bootstrap 区间仅反映这批题目的重采样不确定性，不能代替真实模型重复运行。1,000 题是本预算下保留的既有设计，不是已经完成统计功效分析后的最低样本量。

新划分目录是 `data/experiments/splits/hotpot-dev-seed42-budget-v2`，旧 `hotpot-dev-seed42-v1` 及两轮 smoke 归档保留。两个新配置都将旧开发集 300 题的 manifest 登记为 exposure；旧 smoke 题也在旧开发集中，因而不会进入最终评价。抽样继续使用种子 42 和按题型比例抽样，不根据答题成绩挑题。

离线核验确认：新开发集是旧开发集的子集，含 80 道 bridge 和 20 道 comparison；最终评价仍是原来保留的同一批 1,000 题，含 800 道 bridge 和 200 道 comparison，与新旧开发集均无交集。旧三个 manifest 的文件 SHA-256 与调整前一致。迁移到新机器时，须同时保留新旧划分目录，旧开发 manifest 是明确的曝光登记依赖。

## 执行与复核

配置文件仍为 `experiments/baselines.local.json` 和 `experiments/evaluation.local.json`。准备和预检为离线操作：

```powershell
.\venv\Scripts\python.exe -B -m src.evaluation.experiment prepare --config experiments/baselines.local.json
.\venv\Scripts\python.exe -B -m src.evaluation.experiment preflight --config experiments/baselines.local.json
.\venv\Scripts\python.exe -B -m src.evaluation.experiment preflight --config experiments/evaluation.local.json
```

开发实验仍由用户在项目根目录手动启动：

```powershell
.\venv\Scripts\python.exe -B -m src.evaluation.experiment run --config experiments/baselines.local.json --allow-model-calls
```

开发完成后，先导出开发时段账单、核对计划与券的实际抵扣，再决定是否启动最终评价。将当时实际可用的计划余量与可抵扣券余量相加，减去至少 20 元保留额度，作为评价阶段可用金额；用开发账单目录总价 / 100 估算每道题六方法的费用，再乘 1.5，核对 1,000 题是否仍能覆盖。若超出，须在评价开始前下调题数并另建划分版本，不得看过评价结果后按得分删题。

仅调整规模不能形成费用硬上限；当前 CLI 的 Token 和调用次数限制也不是人民币余额保护。真实输出长度、重试、缓存命中、价格和题目难度都可能改变开销。需要硬停费时，应另外核验并设置控制台提供的预算停止功能；本次仅修改实验规模及离线划分，未更改云账户设置。
