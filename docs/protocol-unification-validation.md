## 协议能力

| 起始模板 ID | 默认行为 | 默认实例 |
| --- | --- | --- |
| `pipeline` | 固定规划 → 检索 → 一次审核 | Planner、Retriever、Validator |
| `pipeline_feedback` | 不足补检索、冲突重规划；分别计数 | Planner、Retriever、Validator |
| `single_expert` | 一个独立作答阶段，检索、作答和引用校验，直接产生最终答案 | 一个 Expert |
| `multi_expert` | 可选规划 → 专家独立作答 → 一次汇合审核；专家默认串行，可改并行 | Planner、两个 Expert、Validator |
| `lead` | 主导者实际选择专家并派发具体任务，汇合只等本轮任务 | Lead、两个 Expert、Validator |
| `debate` | 独立提案 → 质疑 → 修订 → 裁决 | 两个 Expert、Validator |

新建模板统一使用语言 V2，通过同一个按版本分派的校验、归一化、编译入口保存和执行。新增 `answer` 阶段及两种反馈白名单条件。反馈模板默认三次补检索、两次重规划，访问保护覆盖初次执行和全部允许重试（规划三次，检索/审核六次）。节点访问、模型调用、预留 Token、运行及单任务超时保护继续适用。

V1 保留原校验与归一化，不加入 V2 字段，不改变编译版本、旧快照或指纹；V1 三种协议均已离线执行验证。编辑和复制 V1 时仍保持 V1，未提供隐式升级。CLI、原四种兼容流程、schema 1/2 系统和阶段 4.0 V0/V1 实验继续使用既有入口；仅新系统页面撤下旧流程选择框。

`GET /api/v1/protocols/templates` 返回六种模板，以及按语言版本组织的阶段、条件、人数和编辑约束。前端测试目录与该响应逐项比对，避免 UI 白名单漂移。首版仍只支持顺序、单层并行汇合、条件和有限循环，不执行用户代码或表达式。

协议与系统页面在导航时保留编辑状态，返回系统页面刷新选择目录，新增协议仍需用户主动选择。多专家规划开关同步删除或恢复阶段、槽位、入口、读取和连线。列表排序不更改执行次序。
