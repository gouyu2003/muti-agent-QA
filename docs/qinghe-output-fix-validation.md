# Qinghe 双专家输出与耗时修复验收

2026-10-20，用户提供的虚构英文材料，模型为 `deepseek-v4.1-flash`。测试通过进程内 FastAPI TestClient 调用真实模型，使用 `.pytest-live-qinghe-fix/` 隔离存储，没有重启开发服务或覆盖用户系统、知识源及历史记录。浏览器测试按用户要求留待手动进行。

## 修复内容

- JSON 节点请求显式使用 `response_format: json_object`；DeepSeek 模型请求显式使用 `thinking: disabled`。保留实例的模型、提示词、温度和 Token 上限，没有以提高 Token 预算解决延迟。其他模型不发送 DeepSeek 专用 thinking 参数。
- 空正文、截断、非法 JSON、缺失字段及无法定位的引用可在原有重试上限内修正；修正提示明确指出错误，引用仍需匹配实际原文。服务端不会通过补括号接受被截断的输出。
- 多次输出修正失败后标记 `output_error`，不再误报证据不足，不触发补检索。请求异常继续作为运行失败处理。
- 团队专家只需提供自己材料支持的局部事实及引用，并明确缺失项。最终审核者仍负责全题答案；单专家流程仍按完整问题校验。
- 节点轨迹及历史保存各次调用耗时、输出 Token、结束原因、结果类别和请求策略；推理 Token 未提供时保持未知。不会保存模型的思考内容。规划兜底、内部输出重试与流程补检索/重规划分开展示。
- 旧快照和已有历史不重写；新运行使用修正后的 Runtime，代码指纹和每次请求策略均可追溯。

请求参数依据：[DeepSeek JSON 输出文档](https://api-docs.deepseek.com/guides/json_mode/)、[思考模式文档](https://api-docs.deepseek.com/guides/thinking_mode/)。
