# 平台批量评测与对比实验

本模块用于在平台中完成“导入问题库 → 选择固定评测对象 → 创建任务 → 后台执行 → 查看逐题结果和比较报告”。它复用现有协议实现、RunService、运行轨迹、HotpotQA 评分和单写者任务账本，使用独立的任务编排层，不修改原 CLI 实验配置、清单和结果。

## 使用

后端由用户在 VS Code 终端按项目既有方式启动或重启；本次开发不自动启动 8000。打开现有前端，进入侧栏“批量评测”。

页面默认展示“实验任务”，左侧选择任务，右侧通过“结果概览、逐题结果、研究统计、冻结方案”查看详情。“新建实验”分为数据与清单、对比对象、实验设置、校验与创建四步。题库与清单、实验方案、历史档案通过顶部页签独立管理。启动和补跑在操作后弹出模型调用与费用确认，每次操作均需重新勾选。

1. 在“题库与清单”中点击“导入题库”，填写名称、说明并上传 UTF-8 JSON 数组。保存为新问题库，或为已有问题库追加不可覆盖的新版本。
2. 选择问题库固定版本和实验用途（试跑、开发实验、正式评价）。可以生成固定清单、导入原 CLI/平台清单，或在页面生成开发／评价／试跑划分。正式评价必须绑定不可变的评价清单并为每题提供标准答案，不能在任务中再次抽样。开发集与评价集无交集，试跑是开发集子集；评价排除该题库已登记曝光题。
3. 可以选择标准六基线、已发布系统版本，或混合比较，最多 12 个对象、每任务最多 30,000 项问答。同一系统的不同版本与不同系统均可比较；支持运行服务可执行的旧版系统、内置流程和自定义协议（schema-1/2/3，协议语言 V1/V2）。混选标准基线时统一使用逐题 context。配置或材料失效的版本仍列出并说明不可选原因，草稿需先发布。
4. 配置材料、重复数、模型和高级实验条件。标准基线可配置专家数、串并行、检索/规划重试、Lead/Debate 回合和资源/超时上限。用户系统保留已发布流程及资源条件，勾选“统一模型参数”只覆盖本次副本的模型参数。研究设置固定主指标、比较基准、bootstrap 次数和种子。
5. 在最后一步点击“校验方案”，核对实际模型、提示词、流程、资源条件及任务总量。预检不创建任务、不调用模型，页面校验通过后可冻结创建任务。方案、数据或执行环境变化后需重新校验。冻结后在任务详情点击启动，并明确勾选费用确认。
6. 页面每三秒查询状态和结果。关闭页面、关闭前端或重启 Web 后端不会主动终止独立 worker。关闭电脑或结束 worker 会中断；重新打开后，可继续尚未开始的任务。
7. 暂停会等待当前题结束。补跑失败、取消或状态不明项需单独选择；按钮数量按每项最新尝试计算，没有可补跑项时禁用并提示原因。有待补跑项时仍需勾选费用确认。新尝试追加保存，主表始终保留首次尝试，最新尝试统计单列。已成功完成的题不会补跑；绕过页面提交无待补跑项的请求也会被后端拒绝，不启动后台进程。
8. 新任务自动生成按题型/重复次数分层、跨重复标准差、开销均值/中位数/P95和同题配对 bootstrap 95% 区间。配对统计仅在所有首次尝试完整时生成；同题先对重复运行取均值再按题重采样。缺失答案/支撑事实的指标不补零，不计算不完整评分集合的区间。多重比较未经校正，不能仅凭这些区间作整体显著性结论。
9. 可导出研究报告 Markdown、配对差值 CSV、统计 JSON 和完整实验 ZIP（报告、冻结方案、固定清单、逐题结果）。原始逐题 CSV/JSON 和诊断轨迹继续保留。导出不调用模型。旧任务仍按原有格式保留，不在查看时改写历史档案。

## 运行监控与结果审阅

- 任务详情显示当前题目、方法、重复轮次、尝试序号、活动节点/协议阶段、本题耗时与最近轨迹事件。并行节点分别保留，已完成节点从活动列表移除。模型请求期间没有新事件，不直接等同于进程失活。
- 方法进度始终按首次尝试展示；补跑不会把首次失败改成完成。另有最新尝试汇总、全部尝试已知 Token/调用次数，以及首次/最新/全部逐题记录的切换。
- 可按状态、方法、诊断类别和题目/答案文本筛选，分页由后端执行。点击“同题答案对照”查看同一题、同一重复下各方法的完整答案、分数与运行轨迹；执行中或未开始的项保留相应状态。
- 已结束尝试累计耗时与“未开始首次任务的预计剩余”分别展示。预计值仅按已记录首次尝试均值估算，不包含补跑、暂停等待、当前题及报告生成，不是整批墙钟承诺。

## 实验方案复用与任务归档

在“保存与复用实验方案”中，可以保存当前配置、从所选冻结任务保存方案、导出/导入方案 JSON。每次保存生成新的不可变方案 ID 和请求指纹，不覆盖旧方案。方案保留题库、清单、版本和高级条件的引用；当前环境缺少这些引用时需重新选择并校验。

“复制为新实验配置”只填充一个新的可编辑配置，保留源任务 ID，清除预检令牌和费用确认；它既不创建已运行任务，也不启动模型。重新预检、冻结后生成新的任务 ID，原结果和冻结数据不变。

任务列表支持名称/ID、状态及用途筛选。归档只隐藏任务，保留全部数据；勾选“显示已归档任务”可查看和取消归档。运行、排队、等待停止中的任务不能归档，已归档任务不能直接启动或补跑。

## 旧 CLI 档案只读接入

在“旧 CLI 只读实验档案”中，从 `MAQA_EXPERIMENTS_DIR`（默认 `data/experiments/`）的直接子目录选择已经生成报告的 CLI 实验。入口不接受任意文件路径，不递归扫描试验目录，也不运行原脚本。

导入核对原配置、清单、来源和最后报告的指纹，以及任务账本与逐题身份。在原执行锁上以只读方式加锁，拒绝活跃写入、未检查点 WAL 或未核对的 running 尝试。原目录不初始化数据库、不写锁字节、不重评答案、不改写文件。

导入后在平台库内保存独立、带指纹的报告和逐题结果快照；重复导入同一内容返回同一快照。历史视图保留原报告的首次成绩、分母、统计区间和开销，并提供同题对照、筛选及 CSV/JSON 导出。源目录移走或报告变化后，已导入的结果仍可读取；查看原轨迹则要求源目录、来源指纹及运行身份仍一致。历史快照没有启动、补跑或迁移续跑入口，不能用当前源码续接原实验。

题库列表不再自动展示问题正文。主动点击“预览前三题并登记为已曝光”会登记相应 ID；正式评价模式不提供题目预览。曝光按题库管理、跨版本共享。升级时一次性登记已有开发/未标用途的平台试跑任务，不修改原任务档案。平台外或其他题库中的开发/人工接触需显式导入开发/试跑清单或登记 ID，系统无法推断未登记的接触。导入原 CLI 评价清单前应先登记相应开发/试跑历史；上传原始数据文件的新固定版本可保存文件 SHA-256，供原清单核验。

## 问题库

简单回归问题：

```json
[
  {"id": "q1", "question": "Where is Cedar Institute?", "answer": "Northbridge"},
  {"id": "q2", "question": "Who founded Cedar Institute?"}
]
```

`answer` 可省略。无标签的问题只统计完成、失败、用量和耗时，不以零分代替未知正确性。EM/F1 沿用英文 HotpotQA 归一化与分词规则，不宣称是中文或语义等价评分。

也支持原始 HotpotQA 数组：`_id/question/context/answer/supporting_facts/type`。有完整答案和支撑事实时复用原实验的 Answer/SP/Joint 评分及错误诊断；支撑句坐标必须合法，不会自动修正或丢弃异常题。最多 10,000 题、100 MiB。每题 ID 唯一，问题长度不超过 2,000 字符。

材料策略：

- “每题 context”：只向 Runtime 传递该题 ID、问题与上下文，标签留在评分侧。所有检索实例替换为该题上下文，记录原系统版本和派生指纹；属于实验派生执行。
- “系统固定知识源”：只用于用户系统。按原智能体绑定材料回答全部问题；创建任务时复制并核验 corpus/index 及材料原件的固定字节，后续删除原系统或材料不会改变已冻结的评测材料。

## 执行与存储边界

默认存储为被 Git 忽略的 `data/evaluations/`；可通过 `MAQA_EVALUATIONS_DIR` 指定独立目录。目录不得与源码、日常系统/知识源/运行库或 `data/experiments/` 重叠。

- `platform.sqlite3`：问题库版本、冻结任务、任务生命周期。
- `jobs/<任务ID>/`：任务账本、独立 runs.sqlite3、标签隔离上下文、固定材料、运行 JSON、源码归档、执行端点摘要、报告和 worker 日志。
- 后台进程通过同一 Python 环境执行 `python -B -m src.evaluation.platform_worker`，不通过 Web 请求同步等待任务结束；Windows 以隐藏窗口和独立进程组启动。
- 同一评测目录同时只运行一个任务，SQLite 事务和操作系统锁防止重复启动。进程异常退出后以运行库终态对账；不确定是否完成的请求标为 interrupted，默认不会重发。
- 如果任务初始化期间中断、任务表不完整或运行库损坏，恢复会拒绝执行；保留该任务作诊断并新建任务，不手工拼接账本。
- 创建时冻结源码、依赖、提示词、系统/协议、问题库版本及派生配置；恢复还核对首次启动时的模型端点摘要。更改执行条件应新建任务。凭证不进入数据库或归档。
- `complete=true` 表示首次尝试全部产生完成/失败终态，包含失败计零，不代表全部正确。取消或未知中断保持不完整标记。无标准答案的指标显示未知；不同指标显示各自实际评分分母。
- 报告按首次尝试统计质量，补跑单列，所有尝试计入总用量；未知 Token 不记零。实际费用需与供应商账单核对，资源上限不等于人民币余额保护。
- 新实验可在页面完成数据清单、条件冻结、执行和研究报告；先前已完成的 CLI 正式评价仍保留原冻结基线，不能用新任务覆盖其结果。不同入口共用评分和配对估计逻辑，但新工程验证不构成模型效果或论文证据。

既有 CLI 档案需要用户在页面明确选择导入，不自动并入平台运行任务；原实验历史浏览机制继续保留。平台外或据已查看结果进行调参的题目，需要在后续独立评价前登记相应开发/曝光历史，不能将已接触题目重新宣称未接触。本次未开发云端部署、多人权限、分布式队列、金额硬限额或自动多重比较校正。

## API

前缀 `/api/v1/evaluations`：

| 方法与路径 | 用途 |
| --- | --- |
| GET/POST `/question-banks` | 列出版本、上传 JSON 创建版本 |
| GET `/options` | 标准方法与已发布系统版本 |
| GET/POST `/jobs` | 列出任务、冻结新任务 |
| GET/POST `/plans` | 列出/保存不可变实验方案 |
| GET `/plans/{id}/export` | 导出方案 JSON 与指纹 |
| POST `/jobs/{id}/copy-plan` | 复制为新配置，清除预检和启动授权 |
| POST `/jobs/{id}/archive` | 可逆归档；运行中禁止归档 |
| GET/POST `/manifests` | 列出/生成/导入固定题目清单 |
| POST `/splits` | 原子生成开发/评价/试跑清单 |
| POST `/exposures` | 登记已知曝光 ID 或开发/试跑清单 |
| GET `/manifests/{id}/export` | 导出不可变清单 |
| POST `/preflight` | 无模型调用的条件校验与实际方案预览 |
| GET `/jobs/{id}` | 状态、配置摘要、完成后的报告 |
| POST `/jobs/{id}/start` | 明确 `allow_model_calls=true`，可选 `retry_failed=true` |
| POST `/jobs/{id}/stop` | 当前题结束后暂停 |
| GET `/jobs/{id}/results` | offset/limit 分页，包含全部尝试 |
| GET `/jobs/{id}/monitor` | 只读实时运行阶段、耗时及方法进度 |
| GET `/jobs/{id}/compare` | 同题同重复的首次/最新/全部答案对照 |
| GET `/jobs/{id}/runs/{run_id}` | 逐题运行与轨迹 |
| GET `/jobs/{id}/export?format=csv或json` | 本地审阅与导出 |
| GET `/jobs/{id}/report?format=json或markdown或pairs_csv或zip` | 导出新任务的研究统计和完整报告包 |
| GET `/archives/candidates` | 发现可只读导入的本机 CLI 档案 |
| GET/POST `/archives` | 列出/明确导入稳定只读快照 |
| GET `/archives/{id}` | 原报告、来源信息与规范化只读视图 |
| GET `/archives/{id}/results`、`/compare`、`/runs/{run_id}` | 历史结果筛选、同题对照及原轨迹 |
| GET `/archives/{id}/export?format=json或csv` | 导出导入快照，不依赖原报告仍然存在 |

原 `GET /api/v1/experiments` 继续提供历史档案列表，含义不变。
